# W77：后台扫描任务台账与「最近任务」可见性修复（v0.10.36）

## 1. 现象

用户反馈：**「后台扫描全部记录在最近任务中看不到」**。点击「🚀 后台扫描全部股票」
后，页面「后台扫描任务」/「最近扫描任务与结果」里找不到这次扫描的记录；
有时任务明明跑过，下拉框里仍是昨天的 job。

## 2. 只读诊断（生产库 / 代码）

| 证据 | 结论 |
| --- | --- |
| `scan_jobs` 只有 3 条：`#95 market`(11-08 13:53)、`#97 board`(11-08 17:05)、`#99 watchlist`(11-09 01:03) | 每种 `scan_type` 只剩最新一条，历史 job 被删 |
| `_write_scan_batch` 先 `DELETE FROM scan_jobs WHERE scan_type=?` 再插入 | W18「同类型只保留最新一份」把历史记录连同 `scan_results` 一起抹掉 |
| `_bg_store()` 为 `@st.cache_resource` 内存字典，服务 `NRestarts=2`（23:03 重启） | 后台任务记录只存在进程内存，重启 / 跨会话 / W75 清除后全丢 |
| `_persist_or_return` 仅 `results` 非空才写库；`TaskBusyError`、daemon 线程被重启打断、W75 卡住被清除均无落库 | 失败 / 中断的扫描不留任何痕迹 |
| `_bg_running_fragment` 只包住 running 进度条，完成态与「最近扫描任务与结果」在 fragment 外 | 任务跑完页面不 rerun，下拉列表仍是旧的，用户以为「没记录」 |

四条叠加：**成功的历史被删、失败的无痕、内存态重启即丢、页面完成后不刷新**。

## 3. 修复内容

### 3.1 新增持久化台账 `bg_task_log`

- 新表 `bg_task_log`（`schema.sql` + 迁移 `005_bg_task_log.sql`，幂等），
  字段：`id / label / status / done / total / stage / created_at / updated_at /
  job_id / n_results / error / scan_type`。
- 新模块 `mystery/services/bg_task_log.py`：`log_start / log_progress /
  log_finish / recent / mark_stale / prune / status_label`。
- `components._bg_launch` 在**任务启动瞬间**写 running；进度按「每 5 秒或每 50 只」
  节流写；完成 / 失败 / 页面清除均写终态。所有写入异常硬隔离，不影响扫描。
- `mark_stale(600s)` 把进程重启残留的 running 标为 `interrupted`（不删记录）；
  `prune(200)` 每次启动新任务时裁剪，台账不会无限膨胀。

### 3.2 「最近任务」展示全部记录

- `_render_bg_tasks()` 增加「📋 后台任务台账」表格：任务 / 状态 / 进度 /
  扫描 job / 开始 / 更新 / 备注，最多显示最近 20 条，**服务重启后仍可查**。
- `_recent_jobs()` 默认条数 20 → 50；扫描页与系统状态页均增加「🔄 刷新记录」按钮。
- `_bg_running_fragment()` 检测到内存任务刚进入终态时触发**一次**全页刷新
  （打 `_refreshed` 标记防 2s fragment 循环），完成后「最近扫描任务与结果」
  立即出现新 job。

### 3.3 `scan_jobs` 保留有限历史

- `_write_scan_batch` 不再删光同类型旧 job：先插新 job，再按 `id DESC`
  清理排名超过 `KEEP` 的老 job 及其 `scan_results`。
- `KEEP` 默认 **5**（每种 `scan_type` 最多 5 份，全市场约 5×5578 行，
  生产库 2.4G 量级下增量可接受），可用环境变量 `MYSTERY_SCAN_JOB_KEEP` 调整，
  范围 1–50；**设为 1 即回退 W18 旧语义**。
- 新插入的 job 始终保留，清理只作用于同类型的更老 job。

## 4. 行为对照

| 场景 | 修复前 | 修复后 |
| --- | --- | --- |
| 服务重启后看历史任务 | 「暂无后台任务」 | 台账显示全部历史，含 job # |
| 扫描失败（并发锁拒绝 / 异常） | 无任何记录 | 台账记 `❌ 失败` + 错误摘要 |
| 线程被重启打断 / 卡住清除 | 无记录或消失 | `⚠️ 中断` / `🧹 已清除` |
| 连续多次全市场扫描 | 「最近任务」只有 1 条 market | 保留最近 5 条，可逐条看结果 |
| 任务完成瞬间 | 下拉不更新 | 自动刷新，新 job 立即可选 |

## 5. 测试与验证

- 新增 `tests/test_w77_bg_task_log.py`（8 例）：台账生命周期、失败留痕、
  超时中断标记、裁剪保留最新、recent 上限与空库、`scan_jobs` 保留策略、
  `KEEP=1` 回退 W18、跨 scan_type 互不干扰。
- 全量回归：`pytest -q -m "not integration"`。
- 部署后验证：`schema_migrations` 含 `005_bg_task_log.sql`、生产库新表存在、
  Web health HTTP 200、`ActiveState=active` / `NRestarts=0`、工作区干净。

## 6. 兼容性与回滚

- 历史 job 不改动，只影响**新扫描**；旧的下拉选择行为不变。
- 台账表不存在时 `ensure_table()` 惰性补建；写入失败只告警。
- 回退保留策略：`export MYSTERY_SCAN_JOB_KEEP=1`（无需改代码）。
- 台账为附加记录，删表不影响扫描主流程。
