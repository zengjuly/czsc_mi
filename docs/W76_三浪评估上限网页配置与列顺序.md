# W76 三浪评估上限网页配置与结果列顺序

版本 `v0.10.35` · 提交类型：功能增强 + 缺陷修复 · core 零改动

## 一、需求

1. 「三浪评估上限」等参数能在**网页里修改**，并支持**一键还原默认值**（沿用 W74 共振口径面板的体验）。
2. 分析结果的列把「名称」调到「代码」**前面**。

## 二、背景：为什么会有「评估上限」

W75 修复「后台扫描任务一直卡在最后」时引入了超大池三浪自动限流：
全市场 5580 只逐只查库 + 重采样周/月线 + 三浪评估，候选间还要算
O(C²) 纯 Python 相关性矩阵（外推约 25 分钟 / 2.2GB），且收尾阶段不报进度。
因此默认在**结果数 > 500 只**时，只评估按综合评分降序的**前 200 只**，
其余标「未评估」。

这些参数此前**只能通过环境变量设置**，网页无法调整。用户看到全市场
扫描 job #95 里 5378 只「未评估」后提出需求 1。

## 三、顺带修复的 W74 缺陷（重要）

只读实测发现生产共振覆盖层路径是 `.`：

```
RESONANCE_OVERRIDE_PATH = '.'  | exists = True | is_dir = True
override_exists() = True
stderr: 读取共振覆盖层失败，回退空: [Errno 21] Is a directory: '.'
```

根因是 W74 的写法：

```python
Path(os.environ.get("MYSTERY_RESONANCE_OVERRIDE") or "") or (默认路径)
```

`Path("")` 在 Python 里是 `Path(".")` 且布尔值恒为 `True`，所以 `or`
右侧的默认路径**永远不会生效**。后果：W74 网页「保存配置」会写到目录、
「一键还原」删除目录失败、面板永远显示「已自定义」，读取则报
`IsADirectoryError`（被 try/except 兜底成空 dict，表面上口径仍正确）。

W76 统一改为 `runtime_settings.resolve_override_path()`：显式 env 非空才用，
否则落到**包位置推导的绝对目录** `<repo>/data`。修复后生产实测：

```
RESONANCE_OVERRIDE_PATH = /home/ai/ai_runner/stock/czsc_mi/data/resonance_override.json
is_dir = False | exists = False | load = {} | effective = yearline/80
```

> 选择绝对路径而非 `Path("data")`（相对 cwd）或基于 `MYSTERY_DB_PATH` 推导，
> 是为了让 Web（service 无 `MYSTERY_*` env、WorkingDirectory=仓库根）与
> CLI / 日报（shell 可能带 `MYSTERY_DB_PATH`）**读到同一份文件**。

## 四、实现

### 4.1 共享覆盖层基础设施

新增 `mystery/services/runtime_settings.py`（service 层，只读写
`<repo>/data/*.json` 配置覆盖层，**不写业务库**，core 保持零 IO）：

| 能力 | 说明 |
|------|------|
| `RUNTIME_OVERRIDE_DIR` | `<repo>/data`，可由 `MYSTERY_RUNTIME_OVERRIDE_DIR` 整体重定向 |
| `resolve_override_path(env_key, filename)` | 显式 env > 统一目录，修掉 W74 的 `Path("")` 陷阱 |
| `load_override` | 不存在 / 是目录 / JSON 损坏 → 空 dict，绝不抛错 |
| `save_override` | 原子写（`.tmp` → `replace`），避免并发/崩溃留下半截 JSON |
| `clear_override` | 删除文件（一键还原） |

两份覆盖层：

| 文件 | env 重定向 | 用途 |
|------|-----------|------|
| `data/resonance_override.json` | `MYSTERY_RESONANCE_OVERRIDE` | W74 三振共振口径 |
| `data/scan_wave3_override.json` | `MYSTERY_SCAN_WAVE3_OVERRIDE` | W76 三浪扫描参数 |

### 4.2 三浪参数统一入口（稀疏语义）

`scan_wave3_options_effective()` 返回**稀疏 dict**：
`覆盖层文件 → 显式 env（最高优先）`，**未设置的键不出现**，代码默认由
`wave3_scan._env_int(name, 默认)` 兜底。这样 W75 的关键语义
「**仅当 `MYSTERY_SCAN_WAVE3_MAX` 未显式设置时才自动限流**」完全保留
—— 网页覆盖层与 env 等价，两者都算「显式」。

`mystery/services/wave3_scan.py::attach_wave3_to_results` 中 5 个参数的
`os.environ.get` 全部改走该入口；Web / CLI / 日报 / 扫描收尾同口径，
**下次扫描即时热生效、无需重启**。`MYSTERY_WAVE3_EQUITY` /
`MYSTERY_WAVE3_RISK_PCT`（资金口径）保持原 env 读取，不在本次范围。

### 4.3 网页面板

`mystery/apps/web/views/system.py::render_scan_wave3_config()`，挂在
「系统状态」页、紧跟共振面板之后：

- 生效值 vs 生产默认对比表 + 自定义状态；
- 表单：三浪策略开关、自动限流触发阈值、**三浪评估上限（前 N 只）**、铁律严格模式；
- 高级「评估上限模式」：自动限流（默认）/ 固定上限 / 强制全量，后者带 W75 卡顿警告；
- 「保存配置（下次扫描热生效）」与「🔄 一键还原默认值」。

模式与覆盖层写入的对应关系：

| 模式 | 写入 `MAX` 键 | 效果 |
|------|--------------|------|
| 自动限流（默认） | **不写** | W75 自动限流生效，> trigger 只评前 auto_max 只 |
| 固定上限 | `MAX=N` | 显式语义，始终只评前 N 只，`auto_limited=False` |
| 强制全量 | `MAX=0` | 跳过限流，每只都评估（全市场很慢） |

> 面板提示：改动只作用于**新扫描**，已落库的历史 job 三浪列不变，需重扫才更新。

### 4.4 结果列顺序

| 位置 | 改动 |
|------|------|
| `views/scan.py::_scan_table_data` | `'名称'` 移到 `'代码'` 前（首列仍是序号） |
| `views/system.py::view_true_resonance` | 真三振池 dict 改为 名称 → 代码 |
| `reports/excel_report.py::SUMMARY_COLS` | 前两项 `("name","名称")`、`("symbol","代码")` |
| `apps/cli.py` wave3 表 | 表头与数据行同步交换（避免错位） |
| `reports/html_report.py` | 原本即「名称 + 代码」，无需改动 |

配套把 `tests/test_excel_summary.py`、`tests/test_board_column.py` 里硬编码的
`row[0]`（假设首列是代码）改为**按表头名定位**；给 W69/W75 测试加覆盖层
隔离（monkeypatch 到 `tmp_path`），避免用户在网页保存过配置后污染单测基线。

## 六、使用说明

- **改评估上限**：网页 →「系统状态」→「三浪扫描参数」→ 调整
  「三浪评估上限（仅评估评分前 N 只）」→ 保存 → **重新扫描**即生效。
- **一键还原**：点「🔄 一键还原默认值」，回到 触发阈值 500 / 评估上限 200 /
  三浪开启 / 严格模式关。
- **想让全市场每只都评估**：高级模式选「强制全量」，或设
  `MYSTERY_SCAN_WAVE3_MAX=0`。⚠️ 会跳过自动限流，全市场约十几分钟、
  内存数 GB，建议仅小池或离线回测使用。
- **env 优先级最高**：运维可用 `MYSTERY_SCAN_WAVE3_*` 覆盖网页设置。
- **CLI 等价操作**：也可直接编辑 / 删除 `data/scan_wave3_override.json`。
