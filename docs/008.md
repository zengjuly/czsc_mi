# 优化建议与实现方案（基线 0.9.26 / W26）

> **状态（W48 收口注记）：本文 W27 方案已全部执行完毕，仅作历史方案存档。当前实现状态以 `DESIGN_DOCUMENT.md` §9 为准。**

W26 机制已齐。下面只处理三个真实瓶颈，**不升 `rule_ver`、不改 `chip_low` 阈值、不回填 `date < as_of`、不开阶段 6**。建议版本 **0.9.27（W27）**。

当前库的关键数字：5559 只股票里 **86 只有股本快照** → 全市场近 20 日覆盖率 44.5%。自选日报的 `chip_low` 会好得多；全市场扫描仍会大量 unknown。优化优先铺股本，不是改判定。

---

## 优先序

| 优先级 | 项 | 为什么 |
|--------|----|--------|
| P0 | QA 拆自选 / 全市场 | 44.5% 被全市场没快照的票拉低，会误导「派生失败」 |
| P1 | 周日全市场低频 `sync-shares` | 覆盖率的真正分母；AGENTS 允许低频，禁止的是每个交易日全市场打竞价 |
| P2 | 除权筛子扩到回购注销 / 解禁 | 否则事件日仍用旧分母算 `calc_float` |
| P3 | 管线 2/3 步失败可观测 | 现在失败不挡 scan，日报可能带着旧覆盖率静默出去 |

P0 可当天合；P1 一次周末任务就能把有快照只数从 86 拉到数千；P2 依赖先摸清 `raw_adjustment_events` 列名。

---

## P0 — 覆盖率口径拆开

**问题**：`turnover_coverage` 用全部 `type='1'` 股票做分母，没有快照的 5000+ 只永远拉低数字。自选 86 只是否已铺满近 20 日，日报看不出来。

**做**

`turnover_qa_stats` / 日报页脚同时输出两套：

```text
watchlist_n / watchlist_with_shares / watchlist_turn_20_coverage / watchlist_chip_low_unknown
market_n / market_with_shares / market_turn_20_coverage
```

自选覆盖率才是 18:00 验收指标（有快照且有量的票，目标仍是滚满 20 个交易日 ≥95%，凑不到就看 `no_shares` / `skipped_before_asof`，不改阈值）。

**落点**：`sync_turnover.py`、日报组装、`test_turnover_qa.py` 增「codes=自选 vs 全市场」两条断言。

---

## P1 — 周日全市场股本快照（覆盖率主杠杆）

**问题**：周对账现在是 `--watchlist`（86 只）。全市场没有分母，`sync-turnover` 对那 5000 只只能 `no_shares`。

**做（符合「低频、不进 18:00 主链」）**

```text
# 周日独立 cron，不进 daily_pipeline.sh
czsc-mi sync-shares --watchlist   # 先自选（短、必成）
czsc-mi sync-shares               # 全市场，100/批 auction final
```

- 非 `--force`：已有快照且推算股本变化 ≤3% 跳过写入，仍要请求才能比，可加「距上次 `as_of` < 6 天则跳过 HTTP」减批次数。
- `--force` 仅空库/事故。
- 预计 50–60 批；失败断点：已写入的 `thscode` 不重拉（按最新 `as_of`）。
- 周一 18:00 起 `sync-turnover` 才能给全市场填**当日**空 turn；近 20 日全市场覆盖要再滚约 20 个交易日，或对**已有快照的票**人工跑一次：

```text
czsc-mi sync-turnover --backfill-days 20
```

仍禁止 `date < as_of`。

**不做**：每个交易日全市场 snapshot；把全市场 HTTP 塞进 18:00。

**验收**：`market_with_shares` 从 86 升到与 `type='1'` 可交易股票同量级（停牌/无竞价价的允许缺）；自选覆盖率与全市场覆盖率分列可见。

## P2 — 除权事件筛子

**现状**：只认 `per_share_bonus>0 OR allotment_ratio>0`。回购注销、解禁不触发新 `as_of`。

**先探测（半小时，不写业务）**

对本地 MarketDB：

```sql
PRAGMA table_info / DESCRIBE raw_adjustment_events;
SELECT * FROM raw_adjustment_events LIMIT 5;
-- 按列看事件类型枚举
```

把「送转 / 增发配股 / 回购注销 / 解禁上市」映射到真实列（可能是 `event_type`、`adjust_type`、`change_reason` 等）。列不存在就保持现状 + DESIGN 写明缺口，不要猜列名硬筛。

**映射落地后**

```sql
WHERE ex_date >= ?
  AND (
    per_share_bonus > 0
    OR allotment_ratio > 0
    OR <回购注销条件>
    OR <解禁条件>
  )
```

纯现金分红（不改流通盘）必须排除。无新类型命中仍零 HTTP。

单测：夹具里 4 类事件 + 1 只现金分红 → 只请求前 4 只。

**落点**：`find_adjustment_events`、`test_sync_shares_adj.py`、DESIGN §11 一句「事件类型以映射表为准」。

## P3 — 管线失败可观测（仍不阻塞 scan）

保持 2/3 步失败不挡日报，但必须留下痕迹。

**做**

- `daily_pipeline.sh`：2、3 步把退出码写入 `/tmp/czsc-mi-daily.status` 或报告目录 `pipeline_status.json`（`shares_ok` / `turnover_ok` / `qa` 摘要）。
- `scan --report` 页脚加一行：`股本刷新=ok|skip|fail；换手派生=ok|fail`。
- 飞书正文若已有摘要，附同一行。

**不做**：2/3 失败就中止 scan（会没日报）。

金标三只默认开关分差 ≤ 1

无事件日 sync-shares --from-adjustments requested=0
