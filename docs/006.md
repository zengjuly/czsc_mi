## 阶段 2 — 换手率治理（修订：股本低频、换手按日派生）

### 2.1 事实

- DuckDB `v_daily*.turnover` = **成交额**，不是换手。
- tdx `.day` / tdx-api：只有量额，无换手、无流通股本。
- fuyao 日 K / 估值快照：无换手、无股本。
- [集合竞价快照](https://fuyao.aicubes.cn/docs/api-reference/auction/) 有 `float_market_cap`、`last_price`，以及 **竞价换手** `auction_turnover_pct`（不能当全天换手）。
- 流通股数只在送转、增发、回购注销、解禁等事件日变化，**不需要每个交易日更新**。

### 2.2 目标

- 自选近 20 日 `turn` 覆盖率 ≥95%；`chip_low_unknown` 可量化下降。
- 不伪造：无有效换手仍 unknown，不得当 `chip_low=True`。
- 不改 `scan_signals` 的 2% 与低位门。

### 2.3 两层数据

```
float_shares   低频（初始化 / 每周对账 / 事件或跳变）
volume(日)     已有行情链
turn(日)       仅当 turn 为空：volume_股 / float_shares × 100
```

\[
\text{float\_shares} = \frac{\text{float\_market\_cap}}{\text{last\_price}}
\]

\[
\text{turn}_t = \frac{\text{volume}_t}{\text{float\_shares}_{\text{最近快照}}} \times 100
\]

tdx_local 量为「手」时先 ×100。`auction_turnover_pct` 不入库 `turn`。

### 2.4 股本刷新（不是每日任务）

| 触发 | 动作 |
|---|---|
| 空库 / `czsc-mi sync-shares --force` | 按 100 只一批拉 `auction/snapshot?stage=final`，写快照 |
| 每周一次（周末或周一开盘前） | 自选必跑；全市场可选，不进 18:00 主链 |
| 公司行动 | `raw_adjustment_events` / 已同步除权日命中的票当日重拉 |
| 跳变校验 | 新推算股本相对旧值变化 **>3%** 才覆盖（滤掉纯价格波动） |
| 每个交易日 | **不打竞价接口** |

生产用 `final`，不用盘中 `live` 刷股本。

### 2.5 每日只做的事

18:00 管线在行情 sync 之后：

1. 读本地最新 `float_shares`（`as_of <= 当日`）。
2. 仅对 **当日且 `turn IS NULL` 且 volume 有效** 的 K 线写入 `calc_float`。
3. `0 < turn < 80` 才写，否则丢弃并记 QA。
4. 有 `legacy`/`official` 的行 **绝不覆盖**。
5. 近 20 日中间洞：连续缺失 ≤5 日才允许 ffill，并标 `ffill`；再长保持 NULL。
6. **禁止**用当前股本回填快照日之前很久的历史空 turn。

analyze / Web 只读，不现场调竞价。

### 2.6 代码落点

- `adapters/ths.py`：`get_auction_snapshot`
- `core/turnover.py`：纯函数（volume + 单位 + shares → turn）
- `services/sync_shares.py`：低频股本
- `services/sync_turnover.py`：每日空 turn 回算 + 覆盖率日志
- CLI：`sync-shares`、`sync-turnover`（后者可并进现有 `sync` 末尾，只做派生、不打 HTTP）
- `daily_pipeline.sh`：只调 `sync-turnover`；`sync-shares` 单独 cron（周）

### 2.7 QA

每次派生打：`as_of`、自选/全市场近 20 日覆盖率、unknown 率、`turn_source` 分布、异常丢弃数。

**验收**：自选覆盖率达标；金标分数不变；抽检不覆盖旧 turn；代码路径无 `v_daily.turnover → turn`。

## 阶段 3 — 分析结果缓存

**键**：`symbol + trade_date + adjust + rule_ver + chan_enabled + chan_score + czsc_ver + include_detail + bars_fingerprint`  
（指纹：日 K 末根 dt/close/volume + 根数）

**表**：阶段 1 的 `analysis_cache`。收盘后日级有效；盘中短 TTL 或不写。sync 更新该票 K 线则删对应日缓存。

**接入**：只在 `AnalysisService.analyze_one_stock` 头尾读写。先给 daily、Web 二次进入、scan 补详情；全市场扫描用环境变量打开。

**验收**：同票连算第二次命中且字段一致；改开关/`rule_ver`/K 线必 miss。

## 阶段 4 — 扫描提速（不改年线语义）

生产混合分默认关，年线未过时 Mystery 原分仍可能非 0，**不能**用年线预筛跳过 `run_mystery`。

**可做**

- `_analyze_chan` 周/月一律 `resample_bars(daily)`，禁止再 `fetch_bars`。
- 日/周/月 series 在 `analyze_one_stock` 算一次，规则与缠论共用。
- scan worker 复用 `AnalysisService` + 阶段 3 缓存。
- 不增加线程池（GIL 无收益）。

「年线未过直接 0 并 skip 规则」属于改契约，放到阶段 6。

**验收**：默认 scan 与个股页分差 ≤ 1；200 只样本测倍率，不预先承诺数量级。
