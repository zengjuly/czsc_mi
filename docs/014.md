## 一、这是什么

**Mistery 趋势交易论自动化分析系统**：以 czsc（缠论 Rust 内核）做结构识别，迁入
Mystery 规则（三振共振、主升浪、平台、VAP-ATR、年线滤网），输出 Excel/HTML 日报、
Streamlit Web 面板、飞书推送。

分层架构（改代码前必须懂）：

```
apps (CLI/Web/cron)
  → services.analyze/scan/sync   ← 唯一计算入口 analyze_one_stock()
    → core                        ← 纯函数 + dataclass，零 IO，禁 import czsc
    → adapters                    ← 唯一外部依赖出口（czsc/扶摇/tdx/sqlite）
```

两条硬原则：
1. **流程归一**：所有入口（Web/CLI/扫描/日报）消费同一个 `to_dict()` 产物，
   禁止第二套计算路径。
2. **取数归一**：数据只经 MarketDataClient 降级链
   `SQLite → DuckDB → ths_official → tdx_api → tdx_local`，
   禁止直连数据库或旁路 SDK。

## 二、依赖

| 类别 | 内容 |
|---|---|
| Python | **≥3.10**（CI 矩阵实测 3.10/3.11/3.12 全绿） |

| Web 可选 | `streamlit` + `plotly` |

生产库本体是单文件 **SQLite**（`mystery_cache.db`，本机 ~4.9GB，16 张表）。

## 三、安装

```bash
cd /path/to/czsc_mi
python -m venv .venv && source .venv/bin/activate

pip install -e ".[dev]"       # 只跑分析+日报（无缠论、无web）
pip install -e ".[chan]"      # + 缠论结构展示
pip install -e ".[web]"       # + Streamlit 面板
# 全套：pip install -e ".[chan,web,dev]"
```

装完验证：`czsc-mi --help`（入口 = `mystery.apps.cli:main`）。

## 四、配置

**环境变量唯一事实源 = `~/.stockrc`**。`mystery/config.py` 导入时自动 `setdefault`
注入，所以任何入口（含裸 `env -i python`）都能拿到全套；systemd/cron 用
`bash -c 'set -a; source ~/.stockrc; set +a; exec …'`。
**禁止在任何 unit/cron/脚本里新增旁路 `Environment=` 硬编码**（曾因此分叉出两个
TDX 路径）。

`.stockrc` 核心键：

```bash
export MYSTERY_DB_PATH=/path/to/stock/data/db/mystery_cache.db   # 生产库；不配则落 <repo>/data/
export MYSTERY_REPORT_DIR=/path/to/stock/output/                 # 日报落盘目录
export MYSTERY_CHAN_ENABLED=1     # 缠论结构展示，默认开
export MYSTERY_CHAN_SCORE=0       # 混合分开关，默认关（综合分=Mystery 1.22.30 口径）
export THS_FUYAO_SCRIPT=/path/to/Financial-API/python/toolkit/fuyao/scripts/fuyao.py
export THS_MARKETDB_DIR=/path/to/Financial-API/data
export TDX_HOME=/mnt/new_tdx
export TDX_VIPDOC_DIR=/mnt/new_tdx/vipdoc
# 可选：HITHINK_FINANCE_API_KEY（扶摇在线源）、TDX_API_URL
```

注意：
- `MYSTERY_CHAN_SCORE=1` 后输出 `rule_ver=mystery-0.10.0-chan`，
  **勿与 1.22.30-compat 金标比绝对值**。
- 凭据不进 git。Web 登录口令存 `~/.config/czsc_mi/web_auth.json`
  （文件存在即启用登录门，`MYSTERY_WEB_AUTH=*** 或删文件即关；
  `scripts/web_auth_init.py` 交互设口令，<8 位拒写）。
- 飞书 webhook 存 `~/.config/czsc_mi/feishu_webhook`。

数据粒度约束：**最小日线**，周/月线由 `resample_bars` 派生；历史最多 2000 交易日
（约 2018-07 起），无分钟级数据。

## 五、使用

### 5.1 单票分析

```bash
czsc-mi analyze --stock sh600519
```

`to_dict()` 关键键：顶层 `score` / `rule_ver` / `turnover_20` / `chip_low` /
`bars_fingerprint`；`mystery.signal` 内含 综合评分/操作建议/主升浪信号/真三振/
年线滤网/周线锚定/破五反五/共振评分/共振级别/年线条件/详情。
（注意 turnover_20、chip_low 在**顶层**，不在 signal 内。）

### 5.2 数据同步（先把库喂饱）

```bash
czsc-mi sync --period daily --days 365              # 行情，断点续跑
czsc-mi sector-sync                                 # 板块成分股 → stock_sector_rel
czsc-mi sector-sync-kline --days 15                 # 板块K线增量（--full_since 重建，窗口≤3.5年）
czsc-mi sync-shares --watchlist                     # 股本快照（周频即可，>3%跳变才覆盖）
czsc-mi sync-turnover --watchlist --date YYYY-MM-DD # 当日 turn 派生（纯本地零HTTP）
```

### 5.3 扫描与日报

```bash
czsc-mi watchlist import-tdx                        # 从通达信 zxg.blk 导入自选
czsc-mi scan --watchlist --report                   # 自选扫描落库 + Excel/HTML 日报
czsc-mi scan --limit 100                            # 全市场（防呆默认100）
czsc-mi daily --watchlist                           # 只出报告不落库（手动用）
```

全市场扫描自动用 **fork 进程池**（4 进程，`MYSTERY_SCAN_WORKERS` 可调；线程池因
GIL 无收益）。当日 chan 缓存热时约 25–30 分钟，冷约 50 分钟。入口有 flock 互斥，
并发拒绝不排队。

### 5.4 Web 面板

```bash
bash scripts/start_web.sh        # 或 systemd user service czsc-mi-web
python scripts/web_auth_init.py  # 首次设登录口令
```

生产实配：`--server.port 18501` + 自签 HTTPS。验证用
`curl -sk https://127.0.0.1:18501`（探 8501/HTTP 是错的）。
改码后必须 `systemctl --user restart czsc-mi-web`。
详情链接带 `?at=<HMAC token>` 实现跨标签免重登（W48 起 token 三代格式：
`<exp>.<nonce>.<sig>`，绑用户名，改口令即全量吊销；TTL 默认 1 天）。

### 5.5 每日自动化（cron，全程无 LLM）

```cron
30 17 * * 1-5  <marketdb auto-sync>
0  18 * * 1-5  /path/to/czsc_mi/scripts/daily_feishu.sh   # sync→scan→日报→飞书
0 10 * * 0     scripts/weekly_shares.sh                   # 周日全市场股本铺盘
```

日志 `~/.local/state/czsc_mi/daily.log`。

## 六、验收与自检（从 0 部署后按此顺序确认）

1. **QA head 四字段**：日报/扫描启动行
   `db=… kline_max=… as_of_max=… orphan=0`。
   `db=` 必须等于 `$MYSTERY_DB_PATH`（打到仓内同名空库是新手最常见的「0 只快照」
   根因）；`orphan≠0` = 双代码格式回潮，跑 `scripts/merge_suffix_codes.py`。
2. **换手覆盖**：近 20 根有效 turn 应接近满（历史假 0 已由 `clean_turn_zeroes.py`
   洗成 NULL、baostock 已回填 legacy 真值，ckpt 10357 票全覆盖）；
   `chip_low_unknown` 高不是 bug，是「宁缺毋假」设计。
3. **金标对拍**：改动规则后跑 sh600519/sz000001/sh600150 分差 ≤1。
   **必须带管线 env 跑**（裸跑三票全 0 = SDK 缺失回退）；金标不一致但三路径
   max_diff=0 属行情漂移，用 `git stash` 基线对拍法定位；金标集成测自带
   「行情日≠快照日→skip」守卫（W48），跨日 skip 是设计内行为。
4. **测试**：`pytest -m "not integration"`（v0.10.23 基线 **233 passed**）离线全绿
   即可提交；web 冒烟等 integration 测试**永久留本机池，CI 只跑离线集**。
   推送前跑干净 venv（本机全家桶 venv 会掩盖可选依赖缺失）。

## 七、开发者纪律（改码前必读）

- 执行规范在仓库 `AGENTS.md`（受保护文件，改动需用户审批），实现状态在
  `DESIGN_DOCUMENT.md` §9 阶段表（W20–W48 全记录）——这两份是权威，本文只是索引。
- 每次功能改动：pyproject + `mystery/__init__.py` **双处**版本 bump + DESIGN 加
  W 行 + commit 带 `(W##, v0.x.y)` + 更新本机实例（`systemctl --user restart` 等）。
- 轻量 tag 会漏推：push 后 `git ls-remote origin refs/tags/vX.Y.Z` 核实。
- 新增表/列一律走 `mystery/store/migrations/NNN_*.sql`，不塞零散 ALTER。
- 禁止第二套计分：报表/页面/扫描只读 `to_dict` 已有字段。
- sector_code 各表格式不同：`sector_kline` 存 `ths_881155`、`stock_sector_rel`
  存 `881101.TI`、`sector_meta` 混合——查询按各表存储格式归一，勿一律加 `ths_`。
