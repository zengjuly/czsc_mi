## 0. 对照现状核实（先承认的事实）

### 0.1 chan_score 现用因子（`mystery/core/scorer.py:16-41`，逐行核实）

| 因子 | 分 | 备注 |
|------|----|------|
| 无日线结构（`not chan or '1d' not in chan`） | 50 | 早退 |

| 周线末笔与日线同向 / 反向 | +8 / −8 | |

夹紧 [0,100]。混合分 `S = 0.55·S_mystery + 0.25·S_resonance + 0.20·S_chan`（`scorer.py:60-64`），年线滤网未过 → 强制 0（`scorer.py:57-59`）。

### 0.3 开关与 rule_ver 现状（与方案一致，两处要精确化）

- AGENTS §2.5 双开关契约原文核实无出入；「买卖点、背驰等未纳入契约的缠论解释，不得进入默认综合分。要进分必须先改本节并升 rule_ver」在案。
- `combine` 只在 `mix_enabled = chan_enabled() and chan_score_enabled()` 时进入（`services/analyze.py:270-273`），生产默认分关 ✓。
- **精确化 ①**：cache key 里的规则版本是硬编码字符串 `'mystery-1.22.30-compat'`（`analyze.py:247`），`AnalysisResult.rule_ver` 默认取 `RULE_VER` 常量（`models.py:20`）。6C 按开关选 ver 时这两处都要改，不只常量。
- **精确化 ②**：cache key flags 已含 `C{enabled}|S{score}`（`analyze.py:244-245`），6A 新字段写入 ChanStructure 后 **chan_cache 旧条目仍会命中**（czsc_ver 未变）。6A 上线需 bump chan 缓存失效——最简做法：`chan_from_dict` 对缺新字段的老 dict 容忍为空即可（展示层 `-`），或在 6A 提交里将 czsc_ver 探针字符串追加 `+v2` 使全量 miss。倾向前者（旧缓存只是没有新展示字段，无害）。

### 0.4 czsc 信号可用面（**修正方案原文**）

本机 czsc **1.0.1 没有 `czsc.signals` 模块**（`ModuleNotFoundError`）；信号工厂编译进 `_native.abi3.so`，经 `czsc._native.list_signal_names()`（实测 222 个）与 `get_signal_template(name)` 可枚举。相关信号存在：

| 需求 | 可用信号 | 模板 |
|------|----------|------|
| 一买 | `cxt_first_buy_V221126` | `{freq}_D{di}B_BUY1V221126` |
| 二买/二卖 | `cxt_second_bs_V230320` / `V240524` | `{freq}_D{di}W{w}T{t}_第二买卖点V240524` |
| 三买/三卖 | `cxt_third_bs_V230318/19`、`cxt_third_buy_V230228` | 含均线参数 |
| 背驰（MACD 面积） | `tas_macd_bc_V221201/230803/230804/240307`、`tas_macd_bc_ubi_V230804` | `{freq}_D{di}N{n}M{m}#MACD…_BCV221201` |
| 笔状态/趋势 | `cxt_bi_status_V230101/102`、`cxt_bi_trend_V230824/0913` | |

代价与路径：信号须经 `generate_czsc_signals(bars, signals_config)` / `CzscSignals` 引擎逐根滚动生成（init_n=500），**不是 CZSC 对象上现成属性**（`CZSC.signals` 只是 cache dict）。因此：
- **6A 的 `bs_flag`/`divergence` 默认为空**，adapter 只探测存在性，绝不为展示字段引入逐票 ~百毫秒级信号引擎开销；
- 若 6B 标定确认要买卖点/背驰进分，信号生成放 `CzscAdapter.analyze` 内、受 `chan_score_enabled()` 门控（分关零开销），并计入 `engine_ver`/缓存键。
- **不得在 core 自研第二套背驰/分型**（方案原则，AGENTS §2.6 同义）。

## 2. 6A — 加深摘要，不进分（0.9.30）

`ChanStructure` 新增 Optional 字段（默认空，`chan_from_dict` 容忍缺键）：

| 字段 | 含义 | 实现 |
|------|------|------|
| `zs_position` | 现价相对末中枢 `below`/`in`/`above` | close vs 末 zs 的 zd/zg（`_extract` 内算，price=c.bars_raw[-1].close） |
| `leave_zs` | 离开方向 | 末笔 direction + 价出 zg/zd |
| `n_zs` | 中枢数 | `len(zss)` 直接暴露 |
| `last_zs_finished` | 末中枢是否完成 | `zss[-1].finished` |
| `bi_stretch` | 末笔幅度/末中枢高度 | `(high-low)/(zg-zd)`，zd==zg 时 None；6A 只展示 |
| `bs_flag` | czsc 买卖点标签 | **6A 恒空**（§0.4 代价），6C 门控生成 |
| `divergence` | 背驰标记 | 同上 |

验收：分关金标三只分差仍 0；`to_dict` JSON 可序列化；czsc 不可用/engine unavailable 时字段空、分析不崩；老 chan_cache 条目反序列化不报错（新增 1 测）。

## 3. 原则（违反即停，方案原文照录）

- 识别只来自 czsc，经 `CzscAdapter` 变 dataclass；`core` 禁止 `import czsc`。
- 生产默认 `MYSTERY_CHAN_SCORE=0` 保持关；分关路径 ver 继续 `mystery-1.22.30-compat`。
- 分开路径新 ver `mystery-0.10.0-chan`；缓存键含 ver+开关，旧缓存 miss。
- 不在页面/scan 另写一套缠论分。
- 买卖点/背驰未进 ChanStructure 前，不得在 chan_score 里用 magics 猜。
- 年线否决语义不变：只打混合分，不打默认 Mystery 分。

## 4. 6B — 标定表（占位，标定后填写）

样本 ~30 只（金标三只 + 主升 + 年线否决 + 无结构 + 中枢内/上/下各若干），固定日 K 快照。记录现行 S_chan 与拟议因子值，对照 czsc 信号输出人工核。规则表候选（未标定不得进分）：

```text
确认上涨笔 +12      确认下跌笔 -12
价在中枢上 +8       价在中枢内(价格口径) +2      价在中枢下 -8
日周同向 +8         日周反向 -8
二买/三买 +10（无标签则 0）
顶背驰 -10
无日线结构 50
夹紧 [0,100]
```

权重候选：首选维持 `0.55/0.25/0.20`（只加深 S_chan）；`0.50/0.20/0.30` 须 6B 明证且重出混合分金标。

## 5. 6C — 进分（0.10.0）顺序

1. 改 AGENTS §2.5：写明新因子表、权重、「进分仅当两开关都开」。
2. `models.py` 增 `RULE_VER_CH = "mystery-0.10.0-chan"`；**同步 §0.3 两处 ver 引用**改为按 `mix_enabled` 选择。
3. `chan_score()` 只读 6A/6B 字段，缺字段当 0，兼容「无结构 50」。
4. 金标：分关三只与 1.22.30 分差 ≤1；分开三只**新 fixture** 只锁新口径。
5. 验证缓存 miss（key 含新 ver）。
6. 生产 config 不开 `chan.score`；要开用 env 显式开。

## 7. 风险与处理（修订版）

| 风险 | 处理 |
|------|------|
| czsc 信号 API 因小版本变化（1.0.1 已无 `czsc.signals`，工厂在 `_native` .so） | adapter 经 `list_signal_names`/`get_signal_template` 探测，无则字段空；单测 mock ChanStructure 数据，不 mock czsc 内部 |
| 信号引擎成本（init_n=500 逐根滚动） | 只在 `chan_score_enabled()` 时生成；分关/展示路径零开销 |
| 背驰定义争论 | 只采用 `tas_macd_bc_*` 的 czsc 结果，不自写第二套；结论写入 §4 表 |
| 混合分开后排序大变 | 默认 SCORE 关；分开路径单独 fixture |
| 老 chan_cache 无新字段 | `chan_from_dict` 缺键容忍为空，展示 `-`；不强制全量失效 |
