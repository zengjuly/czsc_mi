# W80：日报字段对齐（turnover_20 数值 + chip 标签）（v0.10.39）

## 问题

用户建议 P0：「Excel/HTML 汇总列固定包含：代码+名称、评分、真三振、三浪摘要、
`turnover_20`、chip 相关标签。全部来自 `to_dict()`，对账方便、减少二次计算。」

现状（核查后）：代码+名称（W76 名称在前）、评分、真三振、三浪结论/阶段/位置/
铁律、换手分档、风格 **均已有**；缺的是
- `turnover_20` **数值列**（近 20 日均换手率%），
- chip 相关标签（payload 顶层已有 `chip_low / chip_low_unknown / chip_quiet`）。

另发现口径不一致：HTML 卡片的「筹码低位」标签用的是旧口径
`cyc.avg_turnover < 2.0`（来自 vap_atr 自适应周期），与扫描落库时
`core.scan_signals.classify` 的 `chip_low` 判定（换手 <2% **且** 满足低位门闩）
不同——同一只票可能日报显示「筹码低位」而扫描表不是。

## 落地改动

### 1. 新增共享映射 `mystery/apps/reports/result_fields.py`

放在 **reports 层而非 core**（保持 core 零改动 / 零 IO 约束）。全部只读
`AnalysisResult.to_dict()` / scan payload 的顶层字段，不取数、不重算、不改判：

| 函数 | 输出 |
| --- | --- |
| `turnover_20_value(d)` | 近 20 日均换手率数值（round 2）；缺失/非法 → `None`（**不伪造 0**） |
| `chip_low_text(d)` | 筹码低位三态：`✅` / `❌` / `换手缺失`（unknown 不当 True） |
| `chip_tag_text(d)` | 综合标签：`低位缩量` / `高位缩量` / `换手缺失` / `—` |
| `turnover_source_text(d)` | 换手来源标记：`缺失` / `低换手` / `bar`（顺带回应 P2「区分真实低换手与数据缺失」） |

### 2. Excel（`excel_report.py`）

`SUMMARY_COLS` 在「VAP-ATR突破」后固定新增 4 列（名称仍在代码前）：
`近20日均换手(%)` / `筹码低位` / `筹码标签` / `换手来源`。
`_flat` 只读 payload 顶层字段填充；旧 job payload 缺这些字段时列仍存在、
值兜底（None / 换手缺失），不报错。

### 3. HTML（`html_report.py`）

- 「筹码低位」标签改用 payload 的 `chip_low`（与 Excel/扫描表**同源同口径**），
  旧口径 `cyc.avg_turnover<2` 移除；换手缺失 / 高位缩量分别标注。
- 卡片 metrics 补 `近20日均换手(%)` / `筹码低位` / `筹码标签` / `换手来源`。

## 约束遵守

- **不改评分 / 信号 / `RULE_VER`**；core 零改动。
- 所有新增列都是「只读展示」，不参与任何判定、不触发二次取数。
- chip 判定沿用 `classify` 落库结果，不在报表里另起炉灶重算。

## 测试

`tests/test_w80_daily_fields.py`（5 例）：纯函数三态映射 / Excel 列存在且值来自
payload / 名称在代码前 / 旧 payload 缺字段列仍存在 / HTML 含 W80 字段。
配合既有 `test_excel_summary.py` / `test_report_patterns.py` 全量回归。

## 回滚

纯展示改动，删除 4 列与映射即可回退，不影响任何落库数据或评分。
